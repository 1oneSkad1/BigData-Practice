# Week 6 관찰

## Task 1 — Apriori와 연관 규칙
- 실제 생성 데이터에서 항목 1468→0의 confidence는 0.838710, 반대 방향은 0.003976입니다(공통 support 52). 따라서 1468을 구매한 사람이 0도 구매한다는 방향이 더 유용하며, confidence는 비대칭입니다.
- 최고 confidence 규칙도 1468→0이며 lift는 1.282431입니다. 무작위보다 함께 나타나는 경향은 있지만, 항목 0 자체가 매우 흔하고 희귀 선행항목에서 찾은 규칙이므로 인과관계나 강력한 추천 근거로 단정하지 않습니다. 제공된 작은 예제의 diaper↔beer는 양쪽 support가 같아 confidence도 0.8로 같고 lift는 1.12입니다.
- 2,000개 항목의 전수 쌍 공간은 1,999,000개입니다. Support 50에서 살아남은 1,849개 항목의 가능한 쌍은 1,708,476개이며, 실제 Apriori가 생성해 유지한 피크 카운터는 820,259개입니다. 가능한 모든 쌍을 미리 할당하지 않고 관측된 생존 항목 쌍만 셉니다.

## Task 2 — 임계값과 증가 곡선
- 기본 데이터는 support 1까지 완료되어 실제 머신 한계는 관찰되지 않았습니다(최대 334.15 MB). 별도 확장 데이터에서는 support 50에서 설정한 256 MiB 추적 할당 예산을 넘어 중단했습니다(피크 431.64 MB, 15,900/40,000개 처리). 인위적 예산 중단과 실제 RAM 고갈을 구별했습니다.
- 카운터는 400→200→100→50에서 5.54×, 4.67×, 3.00× 증가했으며, 25 이하에서는 893,456개로 포화되었습니다. 따라서 임계값을 절반으로 낮출 때 항상 같은 배율로 증가하지 않습니다.
- 400→50에서 정답 수는 25.69×, 카운터 수는 77.49× 증가했습니다. Support 50에서는 6,397개 정답을 찾는 데 820,259개 카운터가 필요했습니다. 25→1에서는 카운터가 포화된 반면 정답이 계속 증가했고 support 1에서 둘이 같아졌습니다. 표와 두 그래프는 explosion.md에 기록했습니다.

## Task 3 — PCY와 실제 메모리 비용
- 버킷 1,000,003개를 선택해 충돌을 줄였고, 정답 및 빈도수가 baseline과 정확히 일치했습니다. 피크 쌍 카운터는 820,259→13,324개로 98.4% 감소했습니다. 별도 brute-force와 50개 무작위 사례도 비교했습니다.
- array('I')의 버킷은 4,000,012바이트, 비트맵은 125,001바이트이며 변환 시 둘이 잠시 공존합니다. 버킷을 삭제한 뒤 pass two를 실행합니다. 전체 추적 할당 피크는 baseline 107.87 MB 대 PCY 4.63 MB였습니다. 동일한 고정 support 50의 데이터 prefix 실험에서 2,000개 장바구니는 PCY가 더 컸지만(0.75 대 4.35 MB), 5,000개에서는 절감했습니다(6.71 대 4.41 MB). 교차점은 이 조건에서 2,000~5,000개 사이이며 항목 분포, support, 버킷 수 및 Python 객체 비용에 따라 달라집니다.
- 버킷을 100,003개로 줄이면 쌍 카운터 149,191개, 피크 16.95 MB로 증가했습니다. 10,007개에서는 820,259개, 108.12 MB로 필터 이득이 사라졌습니다. 모든 실험의 정답은 동일했으며 작은 배열의 충돌이 드문 쌍도 pass two에 통과시켰습니다. 시간 최적화가 채점 목표는 아니며 공식 벤치마크에서는 PCY가 더 느렸습니다.
